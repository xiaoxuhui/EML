# EML v1.0.0 阶段性总结

## 版本定位

`v1.0.0` 是 EML 计算台完成第一阶段功能扩展后的稳定版本。程序以 `EML(x, y) = e^x - ln(y)` 为核心，从初始值 `1` 出发，通过符号计算逐步生成新数值，并记录直接公式和完整计算树。

## 已完成能力

- 结构化表达式树及稳定的规范化键。
- 数值去重、公式去重和同一数值的多公式来源。
- 初始值 `1` 保护和被引用数值的删除保护。
- 本地缓存、JSON 保存、导入和清空。
- 符号形式保留：`e`、`π`、`i`、`ln`、根号和 `sin` 不转成小数。
- 整数及基础代数化简。
- 指数、对数和形式化反函数规则。
- 欧拉恒等式、特殊角、虚数分母和第一条欧拉正弦公式。
- 完整计算树的缩放、鼠标拖动、滚轮和 W/A/S/D 平移。
- 单文件发布版本，可在 Windows 浏览器中直接打开。

## 质量状态

- 自动单元测试：71 项通过，0 项失败。
- 交互测试记录：I01-I38 通过。
- 发布文件：`dist/eml-workbench.html`。
- 发布包：`release/EML-v1.0.0.zip`。
- 源代码不依赖第三方运行时库。

## 代码规模

- `src/formula-rules.js`：631 行，是当前增长最快的模块。
- `tests/unit.test.js`：554 行，已不适合继续集中维护。
- `src/app.js`：473 行，同时承担渲染和多类交互职责。
- 完整工程约 5,180 行，单文件发布版约 78 KB。

## 已识别风险

1. 完整计算树会一次性递归构建并全部渲染；深树和共享分支继续增长后可能卡顿。
2. 公式规则依赖 `rewriteNode` 中的先后顺序，新增规则可能影响旧规则。
3. 化简达到 50 轮上限后，界面仍可能允许添加未完全化简的结果。
4. 导入校验没有严格限制表达式字段、常量名称、整数类型和数据规模。
5. 交互测试目前主要依赖人工浏览器验证，尚未形成自动化回归套件。
6. `app.js` 每次操作会重建数值栏和计算树，后续需要减少无关重绘。

## 重构原则

- `v1.0.0` 标签作为行为基线，重构不改变已确认的数学结果和保存格式。
- 先增加保护性测试，再移动或拆分代码。
- 公式规则按数学领域拆分，统一通过规则注册表执行。
- 计算树改为按需展开，并设置明确的规模上限。
- 每个重构阶段都重新生成单文件版本并执行单元及交互测试。
