# EML 计算台设计文档

## 1. 文档信息

- 版本：V0.1
- 状态：基于当前需求的初版设计，允许继续修订
- 实施策略：重写现有小程序，不在 `eml-workbench.html` 的旧逻辑上继续重构
- 需求依据：`doc/需求与测试用例.md`

## 2. 设计目标

EML 计算台是一个可反复生成新数值的符号计算小程序。用户从初始值 `1` 出发，将数值拖入 `EML(x, y)` 的两个输入位，查看符号结果，再主动把结果加入数值栏，逐步构造新的数值。

本次重写需要满足以下目标：

1. 计算结果以符号表达式为主，不把 `e`、`π`、`i`、`ln`、根号自动转换成小数。
2. 计算与“加入数值栏”严格分离，预览结果不会自动污染数值栏。
3. 数值去重、公式去重，同时允许同一数值保存多条不同公式来源。
4. 每条公式都能展开为完整计算树。
5. 公式库可持续增加，不需要反复修改界面代码和存储代码。
6. 最终交付为可在 Windows 上直接打开的单个 HTML 文件。

## 3. 非目标

第一版不尝试实现通用计算机代数系统，也不承诺判断任意两个复杂表达式在数学上恒等。第一版只对公式库能够证明相等的表达式进行合并，无法证明时保留为不同数值项目，避免错误去重。

第一版不提供自由文本公式编辑器。x、y 的输入仅来自数值栏拖放。

## 4. 重写方案

### 4.1 原则

旧页面把显示文字、近似数值、拖放数据、缓存数据和公式来源混在同一个对象中，继续补丁式修改容易再次出现“结果已计算但问号不更新”等状态不同步问题。

新版本采用单向数据流：

```text
用户操作 -> 状态动作 -> 领域计算 -> 新状态 -> 界面统一重绘 -> 自动保存
```

界面不直接修改计算结果，计算模块也不直接操作页面元素。

### 4.2 工程结构

建议源码结构：

```text
EML/
├─ doc/
│  ├─ 需求与测试用例.md
│  └─ 设计文档.md
├─ src/
│  ├─ expression.js       # 符号表达式与规范化
│  ├─ formula-rules.js    # 内置公式库
│  ├─ evaluator.js        # EML 计算、化简与近似计算
│  ├─ derivation.js       # 直接公式与完整计算树
│  ├─ value-store.js      # 数值、公式去重与选择状态
│  ├─ persistence.js      # 缓存、导入和导出
│  ├─ drag-drop.js        # 拖放协议
│  ├─ ui.js               # 页面渲染与交互绑定
│  └─ styles.css
├─ tests/
│  ├─ unit/
│  └─ interaction/
├─ index.html             # 开发入口
└─ dist/
   └─ eml-workbench.html  # 最终可直接打开的单文件版本
```

源码按职责拆分，发布时合并成单个 HTML，用户不需要安装环境或启动服务器。

## 5. 界面设计

页面从上到下分为四个区域。

### 5.1 计算区

显示结构：

```text
EML( [x] , [y] ) = [结果]  [添加]
直接公式：EML(1, 1) = e
```

- x、y 是拖放目标，可直接被新值覆盖。
- 任一输入缺失时，结果显示 `?`，“添加”按钮禁用。
- 两个输入有效时立即计算并显示符号结果。
- 非法结果显示中文错误，“添加”按钮禁用。
- 点击“添加”才提交当前结果。
- 输入被覆盖后，旧的预览结果立即失效并重新计算。

### 5.2 数值栏

- 初始时只包含固定值 `1`。
- `1` 没有删除按钮，任何删除动作也不能删除它。
- 每个数值项目显示其首选符号表达式。
- 项目可拖入 x 或 y。
- 点击项目会选中它，并在底部显示公式详情。
- 除初始值 `1` 外，其他项目可单独删除。
- 当前选中项使用明确的边框和背景状态，不依赖颜色作为唯一提示。

### 5.3 文件操作区

提供“保存列表”“导入列表”“清空非初始值”三个操作。

- 保存：下载版本化 JSON 文件，同时更新本地缓存。
- 导入：先完整校验文件，校验成功后再替换当前数据；失败时不改变现有列表。
- 清空：只删除非初始项目，保留 `1`。

### 5.4 公式详情区

未选择数值时显示空状态。选择数值后分两部分：

1. 直接公式：列出直接得到该数值的所有不同 EML 公式。
2. 完整计算树：对每条直接公式逐层展开 x、y 的来源，直到初始值或内置常量。

示例：

```text
结果：e

直接公式
EML(1, 1) = e

完整计算树
e
└─ EML(1, 1)
   ├─ x: 1（初始值）
   ├─ y: 1（初始值）
   ├─ e^1 -> e
   └─ ln(1) -> 0
```

当同一数值有多条公式时，每条公式拥有独立的计算树，可分别展开或收起。

## 6. 核心数据模型

### 6.1 符号表达式 Expression

表达式使用结构化语法树，不使用字符串拼接参与计算。

```text
Expression =
  Constant(name)              # 1、e、π、i
  Integer(value)
  Neg(child)
  Add(left, right)
  Sub(left, right)
  Mul(left, right)
  Pow(base, exponent)
  Ln(argument)
  Sqrt(argument)
```

每个表达式提供：

- `canonicalKey`：规范化后的稳定标识，用于去重。
- `displayText`：面向用户的符号文本。
- `approximation`：可选的内部近似复数，不作为显示依据。

### 6.2 数值项目 ValueRecord

```json
{
  "id": "value:e",
  "canonicalExpression": { "type": "constant", "name": "e" },
  "canonicalKey": "const:e",
  "displayText": "e",
  "protected": false,
  "derivationIds": ["derivation:..."],
  "createdAt": "ISO-8601"
}
```

初始值 `1` 的 `protected` 固定为 `true`。导入文件不能把它改成可删除状态。

### 6.3 推导记录 Derivation

```json
{
  "id": "derivation:...",
  "formulaKey": "eml(const:1,const:1)->const:e",
  "operation": "EML",
  "xValueId": "value:1",
  "yValueId": "value:1",
  "rawExpression": { "type": "sub", "...": "..." },
  "resultValueId": "value:e",
  "rewriteSteps": [
    { "ruleId": "EXP_ONE", "before": "e^1", "after": "e" },
    { "ruleId": "LN_ONE", "before": "ln(1)", "after": "0" }
  ],
  "createdAt": "ISO-8601"
}
```

推导记录引用输入数值，而不是复制整棵树。显示完整计算树时再递归展开，可减少重复数据。展开时需要记录已访问节点，防止异常导入数据造成循环。

## 7. 计算流程

一次计算分为以下步骤：

1. 读取 x、y 对应的规范表达式。
2. 构造原始表达式 `Sub(Pow(e, x), Ln(y))`。
3. 验证定义域，例如 `ln(0)` 无效。
4. 按公式库进行确定性化简，并记录每一步使用的规则。
5. 生成结果的 `canonicalKey` 和符号显示文本。
6. 生成待提交的 Derivation，但暂不写入数值栏。
7. 用户点击“添加”后，才执行数值与公式去重并保存。

## 8. 公式库设计

每条规则是独立、可测试的数据和变换函数：

```text
规则编号       匹配                 结果
EXP_ZERO       e^0                  1
EXP_ONE        e^1                  e
EXP_LN_POSITIVE e^(ln(a))，a > 0     a
LN_ONE         ln(1)                0
LN_E           ln(e)                1
LN_EXP_REAL    ln(e^a)，a 为实数     a
EULER_IDENTITY e^(i × π)            -1
EULER_NEG_IDENTITY e^(-i × π)       -1
LN_EXP_IPI_PRINCIPAL ln(e^(a ± iπ))，a 为实数  a + iπ（主值）
SUB_ZERO       a - 0                a
SUB_SELF       a - a                0
SUB_NESTED_LEFT a - (a - b)         b
SUB_NESTED_RIGHT (a - b) - a        -b
INTEGER_ADD     m + n，m/n 为整数    对应整数和
INTEGER_SUB     m - n，m/n 为整数    对应整数差
INTEGER_MUL     m × n，m/n 为整数    对应整数积
NEG_DOUBLE      -(-a)                a
ADD_INVERSE     a + (-a)             0
ADD_SUB_CANCEL  (a - b) + b          a
SUB_NEGATIVE    a - (-b)             a + b
SUB_ADDED_LEFT  a - (a + b)          -b
SUB_ADDED_CANCEL (a + b) - a         b
MUL_NEG_ONE     a × (-1)             -a
I_SQUARED       i × i                -1
ADD_ZERO       a + 0 / 0 + a        a
MUL_ONE        a × 1 / 1 × a        a
MUL_ZERO       a × 0 / 0 × a        0
```

规则按明确优先级运行，并反复执行到表达式不再变化或达到安全步数上限。每次变换必须产生不同的 `canonicalKey`，避免规则循环。

第一版中，`√`、`ln`、`i`、`e`、`π` 均由 AST 节点表示，因此显示层不会把它们误转为小数。根式的具体化简规则待需求进一步确定后加入公式库。

## 9. 去重规则

### 9.1 数值去重

优先使用化简后的 `canonicalKey` 去重。例如 `e^1` 经规则化简后得到 `const:e`，因此与 `e` 合并。

内部近似数值不能单独作为去重依据。两个近似值很接近不代表数学上严格相等。只有公式库证明相等或规范表达式一致时才合并。

### 9.2 公式去重

公式标识 `formulaKey` 由以下内容稳定生成：

```text
操作类型 + x 的 canonicalKey + y 的 canonicalKey + 结果 canonicalKey
```

- 相同 `formulaKey` 只保留一次。
- 结果相同但 x、y 或推导不同的公式分别保留。
- 点击“添加”已有公式时，不新增数值，也不新增公式；界面提示“该数值和公式已存在”。
- 点击“添加”得到已有数值但新公式时，只向该数值追加公式来源。

## 10. 状态模型

应用状态集中保存：

```json
{
  "values": {},
  "derivations": {},
  "valueOrder": ["value:1"],
  "inputXId": null,
  "inputYId": null,
  "preview": null,
  "selectedValueId": null,
  "notice": null
}
```

所有操作通过明确动作完成：放入 x、放入 y、添加结果、选择数值、删除数值、导入、清空。每个动作返回完整的新状态，随后统一重绘界面并按需保存。

删除数值时，如果该数值已被其他公式引用，第一版采用“禁止删除并说明引用关系”的保护策略，避免计算树断裂。后续若需要级联删除，应另行确认。

## 11. 本地存储与文件格式

使用新的缓存键 `eml_workbench_v2`，不直接复用旧页面的缓存结构。

导出文件结构：

```json
{
  "schemaVersion": 2,
  "app": "EML Workbench",
  "savedAt": "ISO-8601",
  "values": [],
  "derivations": [],
  "valueOrder": []
}
```

导入流程：解析 JSON、校验版本、校验字段、检查引用完整性、检查是否存在循环、强制补回受保护的初始值 `1`，全部成功后才替换当前状态。

旧版缓存只有近似数值，缺少可靠的完整公式来源。V2 默认不自动迁移旧缓存，避免把错误数据带入新系统。是否提供一次性旧数据导入工具，后续单独决定。

## 12. 错误处理

- x 或 y 缺失：结果为 `?`，添加不可用。
- y 为 0：显示“ln(0) 未定义”，添加不可用。
- 化简超过安全步数：保留当前符号表达式，显示非阻断提示。
- 导入文件无效：显示具体中文错误，当前数据不变。
- 拖放数据无效：忽略放置并显示提示。
- 删除受保护或被引用数值：阻止删除并说明原因。
- 本地缓存写入失败：不影响当前计算，提示用户导出文件备份。

## 13. 测试设计

### 13.1 单元测试层次

1. Expression：构造、规范化、显示和 canonicalKey 稳定性。
2. Formula Rules：每条规则的正例、反例及组合化简。
3. Evaluator：EML 计算、定义域检查、推导步骤记录。
4. Value Store：数值去重、公式去重、多公式追加、初始值保护。
5. Derivation：直接公式生成、完整树展开、循环保护。
6. Persistence：保存、恢复、错误文件拒绝和引用完整性。

`需求与测试用例.md` 中的 U01-U17 均作为必须通过的验收测试。

### 13.2 交互测试

交互测试在真实浏览器中覆盖拖放、覆盖输入、结果预览、添加按钮状态、数值选择、计算树展开、删除保护、保存、导入和刷新恢复。

`需求与测试用例.md` 中的 I01-I14 均作为必须通过的验收测试，并补充桌面与窄屏两种视口检查，确保长公式不覆盖按钮或其他内容。

### 13.3 回归要求

每增加一条公式规则，至少增加：

- 一条应命中的测试。
- 一条不应误命中的测试。
- 一条与现有规则组合运行的测试。
- 必要时增加数值去重和公式树显示测试。

## 14. 实施顺序

1. 建立 Expression、规范化和符号渲染。
2. 实现公式库及 EML evaluator。
3. 实现 Value Store、双重去重和推导记录。
4. 实现缓存、导入和导出。
5. 构建计算区、数值栏与公式详情区。
6. 接入拖放与输入覆盖。
7. 完成单元测试和交互测试。
8. 打包为单个 HTML，并在 Windows 浏览器中验收。
