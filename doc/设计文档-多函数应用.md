# 设计文档：多函数应用

- **Status**: APPROVED
- **Date**: 2026-10-03

## 模型

函数应用由内置 EML 与用户函数并列组成。用户函数状态为：

```text
customFunctions: [{ id, definitionText, inputValueIds }]
```

`id` 是稳定本地标识；公式来源继续保存 `functionDefinition` 与参数输入 ID，因此删除定义不会破坏既有推导。`customFunction` 是旧格式兼容字段，仅在导入时读取并迁移，不再写入新状态。

## 交互

“函数应用”从 EML 行开始，随后按定义顺序显示每个用户函数。每行用 `custom:<functionId>:<parameterIndex>` 标识输入槽位，避免函数之间覆盖输入状态。定义区提交后添加一行；删除定义仅删除该函数的应用行和定义列表项。函数体的 EML 参数可使用 `0`、`1`、`e`、`i`、`π` 等基础常量。

函数体 AST 除 `EML` 外允许具名调用节点。保存新函数时，调用目标必须是既有用户函数，因此定义依赖总是指向更早保存的函数，天然避免循环。求值时递归展开具名调用，并合并被调用函数的化简步骤。

## 验证

单元测试覆盖多定义、独立输入、去重和迁移。静态界面测试断言 EML 与多个函数处于同一个应用区域，定义区不承载计算行。浏览器测试补测点击/拖放、添加和删除定义。
