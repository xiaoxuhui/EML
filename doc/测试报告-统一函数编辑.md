# 统一函数编辑测试报告

日期：2026-10-29。

## 功能

函数表达式使用与应用相同的input-slot、formula-name与标点样式。
叶子始终留在参数框里，可拖入覆盖。固定数值及来源数值复用setMath和数值栏KaTeX数学排版。
函数、变量、定义数值和数值栏共用指针拖动；超过6px出现可见跟手预览与投放高亮。
预览保留数学DOM、不挡投放、原来源变淡不移位；松手/取消/丢失捕获后清除。
触摸轻点来源采用显式激活并防止原生click重复触发。存档格式和求值器保持不变。

## 实际验证

- `node --test tests/*.test.js`：180/180通过。
- `node scripts/test-function-structure.cjs`：原结构桌面/移动流程及新增桌面鼠标/手机真实触摸流程均通过。
- 桌面1440×1000、手机390×844。手机新流程使用CDP touchStart/touchMove/touchEnd和touchCancel，
  不以tap代替拖动；帧同步后检查中途高亮和跟手预览。
- 对比定义空框与应用空框的宽、高、内边距、边框和字体；根式、分数、指数与数值栏KaTeX DOM逐项一致。
- 实测已填槽覆盖、多层函数、右键删除、键盘结构查看、保存/编辑/取消和缓存不变。
- 鼠标验证两处数值来源拖到原应用；手机验证选择数值后点击输入槽，EML(1,1)=e。
- 无效投放不修改输入/缓存，手机取消拖动不填槽；随后正常触摸和轻点仍可用。
- 中途预览保留源内容、pointer-events:none、跟随指针，结束后预览/源变淡/目标高亮全部消失。
- 已检查实际拖动中的desktop/mobile截图以及统一编辑器截图，未发现重叠或整页横向溢出。
  本地图像在 `_browser_test/function-structure/drag-desktop.png`、`drag-mobile.png` 及 `unified-*.png`，未提交。
- 所有浏览器测试使用独立context和合成夹具，不读取用户原始存档，也不刷新用户正在使用的页面。

## 边界

触摸验证为Chromium设备模拟，不代表Android WebView真机。跨屏拖动不自动滚屏，
手机跨屏仍可通过选值/点槽回退。此次没有修改数学化简规则、没有发布大厅资源或APK。
