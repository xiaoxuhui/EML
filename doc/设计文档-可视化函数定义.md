# 设计文档：可视化函数定义

- **Status**: IMPLEMENTING
- **Date**: 2026-10-04

## 设计

定义草稿仅保存在页面内存中，结构为 `{ name, parameterNames, body }`。`body` 复用组合函数 AST：`eml`、`call`、`parameter`、`constant`。空输入槽以 `null` 表示；保存时不得出现空槽。

函数库、参数区和数值栏提供拖放源。表达式根和每个调用参数槽都是拖放目标。点击槽位会设置当前目标，随后点击任一源也会写入同一目标。新函数可以覆盖选中的槽；这使编辑不需要额外的删除箭头或弹窗。

拖放是主交互：函数落入表达式槽后立即创建对应数量的空槽。为兼容无法拖放的环境，点击采用“先选择来源、再点击目标槽”的两步回退，不会因点击函数而直接覆盖表达式。每个已保存函数有“编辑函数”入口；编辑时锁定函数名和参数，避免破坏其他函数的调用约定，仅更新函数体并保留当前应用输入。

表达式节点使用右键删除。叶子节点（变量、固定数值）删除后替换为同位置的空槽；函数节点仅在其全部输入为空时允许删除，防止一次右键误删嵌套公式。

数值栏拖入时复制该数值的规范表达式和显示文本为 `constant` 节点。因此定义 `f(x) = EML(x, ln(2))` 在 `ln(2)` 从数值栏删除后仍可求值。自定义函数保存 `definitionAst`，旧的 `definitionText` 保留为可读显示和旧存档兼容字段。加载旧记录时仍从文本解析。

数值栏常量还保存原值 ID；完整计算树会沿该 ID 继续构建来源。旧定义缺少该 ID 时，以显示表达式匹配现有数值栏。用户函数调用求值时，将每个实参的 EML 子树重新嵌入被调函数树，确保 `eml`、`exp`、`ln` 等嵌套调用不会被压缩成单个数值叶子。

组合求值入口统一接收 AST 定义。文本定义继续由 `parseDefinition` 创建 AST；可视化编辑器由 `createDefinition` 验证 AST 后创建相同形状的定义。因此后续函数调用、完整计算树和公式保存无需另起一套求值逻辑。
